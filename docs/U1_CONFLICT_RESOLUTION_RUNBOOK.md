# U1-T6 Runbook: Разрешение конфликтов профилей

Дата: 2026-02-25  
Трек roadmap: `U1-T6`

## Цель

Стандартизировать ручное разрешение конфликтов при объединении пользователей в `GlobalUsers`
до включения полного `global-first` режима.

## Что считаем конфликтом

Конфликтом считаются расхождения по одному и тому же телефону между городами, когда для полей:
- `firstName`
- `secondName`
- `gender`
- `birthday`
получены разные валидные значения.

## Источник отчета по конфликтам

Используется существующий dry-run:

```bash
npm run global-users:dry-run
```

Отчет создается в `docs/reports/global-users-dry-run-*.json`, секция:
- `conflicts`

## Правило приоритета (текущая реализация)

1. Основной профиль берется из локальной анкеты с максимальным:
   - `lastActivityAt`, иначе
   - `updatedAt`, иначе
   - `createdAt`.
2. Пустые значения не должны перетирать непустые.
3. Для дублей внутри одного города миграция `apply` блокируется
   (или пропускает конфликтные телефоны при `--allow-city-duplicates`).

## Ручной процесс разрешения

1. Запустить:
```bash
npm run duplicates:phones
npm run global-users:dry-run
```
2. Для каждого `phone` из `conflicts` выбрать эталонный профиль:
   - по активности анкеты;
   - по подтвержденным данным оператора;
   - с учетом актуальной роли/статуса в городе.
3. Привести локальные `Users` к выбранному эталону.
4. Повторить dry-run до приемлемого уровня конфликтов.
5. Выполнить backfill:
```bash
npm run global-users:backfill:apply
```
6. Проверить связность:
```bash
npm run verify:global-links
```

## Критерии готовности

- Нет дублей телефона внутри одного города.
- Конфликты в `global-users-dry-run` либо устранены, либо явно задокументированы.
- `verify-global-links` не содержит критичных расхождений по `globalUserId` и `cityProfiles`.
