# Доменная модель (практический словарь)

## 1. Базовые сущности

### Пользователь (`Users`)
- Локальная анкета пользователя в конкретном городе.
- Ключевые поля:
  - контакты: `phone`, `email`, соцсети
  - профиль: ФИО, пол, дата рождения, фото, статусы
  - доступ: `role`, `status`
  - auth: `password`, `registrationType`, `authProviders`
  - коммуникации: `notifications`, `consentToMailing`
- Источник: `schemas/usersSchema.js`, `server/authOptions.js`

### Глобальный пользователь (`GlobalUsers`)
- Сущность для связки одного человека между городами.
- Хранит связи `cityProfiles` и список `cities`.
- Нужна для мягкого межгородского перехода и устранения дублей.
- Источник: `schemas/globalUsersSchema.js`, `docs/GLOBAL_USERS_ARCHITECTURE.md`

### Мероприятие (`Events`)
- Офлайн-событие пространства.
- Важные поля: дата/время, адрес, статус, лимиты участников, публичность.
- Часто связано с `EventsUsers`, платежами и достижениями.

### Запись на мероприятие (`EventsUsers`)
- Связка `userId <-> eventId` + статус участия.
- Типовые статусы: `participant`, `reserve`, и служебные состояния.

### Роли (`Roles`)
- Настройки прав доступа и уведомлений.
- Влияют на отображение UI и доступность API-операций.

### Рассылка (`Newsletters`)
- Описывает отправки пользователям по каналам и сегментам.
- Исполнение привязано к cron-процессам.

### Город (`GlobalContent.cities`)
- Глобальный справочник городов (`slug`, `title`, `status`, feature flags).
- Используется для публичного селектора и guard-логики.

## 2. Границы города
- Практически все бизнес-данные пользовательского контура локационные.
- Глобально храним только то, что должно быть единым:
  - каталог городов
  - политики города
  - некоторые глобальные контентные блоки
  - `GlobalUsers`

## 3. Смысловые статусы города
- `active`: город полноценно работает.
- `closing`: ограничение новых операций, сохранение доступа к истории.
- `archived`: город скрыт из публичной выдачи, данные сохраняются.

## 4. Термины продукта
- "Пространство" — система офлайн-встреч, а не чат/онлайн-дейтинг.
- Приоритет сценариев знакомств:
  дружеские + деловые + социальные, романтические не единственный фокус.
- Основная ЦА: 30-50.

## 5. Бизнес-инварианты
1. Безопасность и доверие выше скорости изменений.
2. Приватность выше маркетинговых задач.
3. Для API в изменяемых местах придерживаться унифицированного envelope.
4. Изменения не должны ломать мульти-локационный режим (`krsk`, `nrsk`, `ekb`).
