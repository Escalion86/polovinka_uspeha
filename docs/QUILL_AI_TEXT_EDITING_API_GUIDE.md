# QuillEditor: API редактирования текста через ИИ

## Назначение
Инструкция описывает текущую реализацию ИИ-редактирования текста в проекте `Половинка успеха`, чтобы другой ИИ мог перенести такой же механизм в другой проект.

Документ покрывает:
- клиентский флоу (кнопка `ИИ` в `QuillEditor`);
- HTTP API `/api/deepseek`;
- формат payload и ответов;
- обработку ошибок;
- правила преобразования текста до/после ИИ;
- сохранение/загрузку пользовательских промптов.

## Архитектурный поток
1. Пользователь нажимает кнопку `ИИ` в тулбаре редактора.
2. Открывается модальное окно ИИ.
3. Модалка собирает `content`:
- опционально очищенный текущий текст редактора;
- текст запроса пользователя.
4. Клиент отправляет `POST /api/deepseek`.
5. Сервер проксирует запрос в DeepSeek через OpenAI SDK-совместимый клиент.
6. Клиент получает ответ, форматирует его в безопасный HTML и показывает предпросмотр.
7. По кнопке `Подставить в текст` HTML ответа заменяет текст в редакторе.

## Точки интеграции на клиенте

### 1) Кнопка `ИИ` в редакторе
- В тулбар добавляется кнопка `ИИ`.
- По клику открывается модальное окно ИИ.

### 2) Модальное окно ИИ
Основные входные параметры:
- `currentHtml` — текущий HTML редактора;
- `includeCurrentText` — передавать ли текущий текст в запрос;
- `initialPrompt` — стартовый текст промпта;
- `section` — логическая секция для сохраненных промптов;
- `onApply` — callback для вставки результата в редактор.

## Основной API: `/api/deepseek`

### Endpoint
- `POST /api/deepseek`

### Request JSON
```json
{
  "content": "string",
  "deep": false
}
```

Поля:
- `content` (string, обязательно): итоговый пользовательский prompt.
- `deep` (boolean, опционально):
  - `false` или отсутствует -> модель `deepseek-chat`;
  - `true` -> модель `deepseek-reasoner`.

### Серверная логика
- Провайдер:
  - SDK: `openai`
  - `baseURL`: `https://api.deepseek.com`
  - `apiKey`: `process.env.DEEPSEEK_KEY`
- Запрос к модели:
```js
openai.chat.completions.create({
  messages: [
    { role: 'system', content: 'Напиши ответ на русском языке' },
    { role: 'user', content },
  ],
  model,
})
```

### Response JSON (как реализовано сейчас)
Успех:
```json
{
  "success": true,
  "data": {
    "id": "...",
    "choices": [
      {
        "message": {
          "content": "..."
        }
      }
    ],
    "usage": {
      "total_tokens": 123
    }
  }
}
```

Ошибка (не `POST`):
```json
{
  "success": false,
  "error": "Wrong method"
}
```

Примечание: этот endpoint не полностью соответствует общему целевому формату ошибок из `AGENTS.md`. Для 1:1 переноса в другой проект повторяйте текущее поведение. Если нужен унифицированный контракт, нормализуйте отдельно.

## Как формируется `content` на клиенте

В модальном окне ИИ:
1. Если включен флаг передачи текущего текста, `currentHtml` конвертируется в текст:
   - `<br>` -> `\n`
   - `</p>` -> `\n`
   - `<li ...>` -> `\n• `
   - `</li>` -> удаляется
2. Затем текст очищается `DOMPurify` с пустым whitelist (`ALLOWED_TAGS: []`).
3. `&nbsp;` заменяется на пробел.
4. Итоговые части (`текущий текст` + `prompt`) объединяются через двойной перенос строки.

## Как читается и форматируется ответ ИИ
Клиент извлекает:
```js
result?.data?.choices?.[0]?.message?.content?.trim()
```

Далее выполняется форматирование в HTML:
- `**text**` -> `<b>text</b>`
- `__text__` -> `<u>text</u>`
- `~~text~~` -> `<i>text</i>`
- `--text--` -> `<del>text</del>`
- `<<url>>` -> `<a href='url' target='_blank' rel='noopener noreferrer'>url</a>`
- `\n` -> `<br>`

И затем обязательная очистка `DOMPurify` с whitelist:
- теги: `b`, `br`, `i`, `u`, `del`, `strong`, `em`, `a`
- атрибуты: `href`, `target`, `rel`

## Ошибки и валидация на клиенте
- Если пусты и prompt, и текущий текст для передачи: ошибка.
- Если HTTP-ответ не `ok`: ошибка.
- Если `success !== true`: ошибка.
- Если пустой `choices[0].message.content`: ошибка.
- Во всех ошибках модалка показывает уведомление `Не удалось получить ответ от ИИ`.

## Сохраненные промпты (опциональный блок)

### Коллекция
- `AiPrompts`:
  - `title: string`
  - `prompt: string`
  - `section: string`
  - `userId: string`

### API маршруты
- `GET /api/{location}/ai-prompts` — список
- `POST /api/{location}/ai-prompts` — создать
- `PUT /api/{location}/ai-prompts/{id}` — обновить
- `DELETE /api/{location}/ai-prompts/{id}` — удалить

Роуты работают через универсальный `CRUD('AiPrompts', req, res)`.

## Минимальный чек-лист для переноса в другой проект
1. Добавить кнопку `ИИ` в тулбар редактора.
2. Добавить модалку с полями:
- `prompt`,
- чекбокс `передать текущий текст`,
- предпросмотр ответа,
- действие `подставить в текст`.
3. Реализовать `POST /api/deepseek` (или аналог) с контрактом выше.
4. Добавить очистку HTML до отправки и после ответа (DOMPurify/аналог).
5. Добавить безопасный рендер предпросмотра.
6. (Опционально) добавить CRUD сохраненных промптов по пользователю и секции.

## Быстрый пример запроса
```bash
curl -X POST http://localhost:3000/api/deepseek \
  -H "Content-Type: application/json" \
  -d "{\"content\":\"Сократи текст до 500 символов и оставь дружелюбный тон\",\"deep\":false}"
```

## Быстрый пример извлечения результата на клиенте
```js
const response = await fetch('/api/deepseek', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ content, deep: false }),
})

const result = await response.json()
const aiText = result?.data?.choices?.[0]?.message?.content?.trim() || ''
```
