# AGENTS.md — инструкция для нового ИИ-агента

## Назначение
Этот файл нужен для быстрого и безопасного онбординга нового ИИ в проект.
Цель: одинаково хорошо поддерживать разработку новых функций и сопровождение продакшена.

## Дорожная карта
- Актуальная дорожная карта проекта: `docs/ROADMAP.md`.
- При планировании и реализации задач ИИ обязан сверяться с roadmap и приоритизировать работу в его логике.
- Если roadmap обновляется, ИИ должен:
1. Обновить `docs/ROADMAP.md`.
2. Обновить версию в `package.json` (patch-увеличение).

### SemVer правила
- `patch` (`X.Y.Z -> X.Y.(Z+1)`):
  - багфиксы, косметические UI/UX-правки, небольшие доработки без breaking changes.
- `minor` (`X.Y.Z -> X.(Y+1).0`):
  - новая функциональность с обратной совместимостью (новые экраны, виджеты, фильтры, интеграции без ломки текущих API/потоков).
- `major` (`X.Y.Z -> (X+1).0.0`):
  - любые несовместимые изменения (breaking changes): изменение контрактов API, обязательные миграции, удаление/ломка существующего поведения.

### Практика для roadmap
- Закрыт один обычный roadmap-пункт без breaking changes: `patch`.
- Закрыт крупный функциональный блок/эпик (несколько связанных задач с новой ценностью): `minor`.
- Есть breaking changes: `major`.
- Перед любым повышением `major` версии обязательно запросить подтверждение у пользователя и выполнить bump только после явного согласия.

## Что это за проект
`Половинка успеха` — платформа для знакомств и живых встреч через офлайн-мероприятия.
Пользователь регистрируется, выбирает локацию, записывается на события, взаимодействует с организаторами и получает уведомления.

## Философия и миссия
- Миссия проекта: создавать пространство легкости и живого общения.
- Ключевая идея: атмосфера, где человек может быть собой, отдыхать от суеты, общаться естественно, без масок и давления.
- Приоритет в знакомствах: дружеские, деловые и социальные связи; романтические знакомства важны, но не являются единственным фокусом.
- Продуктовый формат: живые офлайн-встречи и мероприятия (вечера, выезды, игры, прогулки, мастер-классы и др.), а не «просто онлайн-общение».
- Проект масштабируется в разные города, поэтому решения должны быть переносимыми между локациями.

## Целевая аудитория
- Ядро: активные занятые люди 30-50 лет.
- Основной ожидаемый результат для участника: сочетание новых связей и потенциальных отношений (`оба направления важны`).
- Не целевой сегмент: молодежь до 25 лет.
- Ограничения доступа и поведения: недопустимо антисоциальное поведение; участники с активными зависимостями не являются целевой аудиторией.

## Продуктовые принципы
- Безопасность и доверие важнее скорости релиза и маркетинговых экспериментов.
- Приватность выше маркетинга.
- Коммуникация проекта: тепло, вдохновляюще, уважительно, душевно, с акцентом на возможность быть собой.
- Модерация встреч и качество среды важны для продукта и должны сохраняться при любых изменениях.
- Сценарий участия должен оставаться простым: выбрать событие -> зарегистрироваться -> прийти на встречу без лишних барьеров.

## Источник позиционирования
- При споре формулировок философии/тона ориентироваться в первую очередь на страницу `/<location>` и ее контентные карточки.
- Ключевые тексты хранятся в `app/_components/location/LocationIndexClient.jsx` и в настраиваемом контенте `siteSettings.aboutSpaceCards` (см. `layouts/content/AboutSpaceContent.js`).
- Устаревшие формулировки в legacy-блоках не считать главным источником продуктового позиционирования.

## Технологический контур
- Next.js 16, React 19
- Гибрид роутинга: `app/` + `pages/`
- MongoDB + Mongoose
- NextAuth (credentials + telegram)
- Jotai (глобальное состояние)
- Tailwind + Flowbite + MUI
- Интеграции: TELEFONIP, Telegram, WhatsApp, DeepSeek

## Карта проекта (важно)
- `app/` — актуальные страницы (App Router) и клиентские entry-компоненты по локациям
- `pages/` — legacy/доп. страницы и API routes
- `pages/api/` — серверные endpoint'ы
- `components/` — переиспользуемые UI-компоненты
- `layouts/` — карточки, контент, модалки, обертки
- `state/` — Jotai atoms/selectors/async-логика (включая систему модалок)
- `server/` — серверная бизнес-логика и интеграции
- `schemas/` — схемы Mongoose
- `utils/` — инфраструктурные утилиты (`dbConnect` и др.)
- `helpers/` — прикладные helper-функции/константы
- `docs/` — документация, которую нужно читать в первую очередь
- `_old_files/` — архив старых файлов проекта; не удалять и не использовать для анализа/реализации задач, если это явно не запрошено.

## Обязательные правила для ИИ
- Поддерживать все локации всегда: `krsk`, `nrsk`, `ekb`.
- Не делать изменений "только для одной локации", если это явно не согласовано.
- Для новых/изменяемых API соблюдать единый формат ответа:
  - успех: `{"success": true, "data": ...}`
  - ошибка: `{"success": false, "data": {"error": {"type": "...", "message": "..."}}}`
- При работе с телефонией ориентироваться на `docs/TELEFONIP_PORTING_GUIDE.md` как на эталонный flow.
- Сохранять текущий стиль кода и именования.
- Использовать функциональные React-компоненты и проп-тайпинг.

## Продуктовые метрики (ориентир)
- Рост повторных посещений мероприятий.
- Рост среднемесячной прибыли через высокорезультативные форматы мероприятий.
- Рост среднемесячного количества участников на мероприятиях.

## Критичные зоны (повышенная осторожность)
- Авторизация и сессии (`server/authOptions.js`, login/register flow)
- Рассылки и уведомления (Telegram/WhatsApp/email, `pages/api/cron.js`, `server/sendNewsletterMessages.js`)
- Роли и права доступа (role settings, проверки в UI/сервере)
- Система модалок (Jotai + `state/modalsFuncAtom.js` + `layouts/modals/*`)

## Порядок действий при неопределенности
1. Сначала искать информацию в `docs/*`.
2. Затем проверять реальное использование в `server/*`, `pages/api/*`, `state/*`.
3. Только после этого предлагать изменение или задавать уточняющий вопрос.

## Минимальный чек перед сдачей изменений
1. Запустить проект: `npm run dev`.
2. Проверить линтинг: `npx eslint .`.
3. Убедиться вручную, что не сломаны критичные сценарии:
- вход/регистрация
- роли и ограничения доступа
- модалки в затронутом разделе
- рассылки/уведомления (если затрагивались)

## Безопасность и данные
- Никогда не выводить секреты и токены в ответах/логах.
- Не коммитить `.env*` и чувствительные данные.
- Не логировать персональные данные без необходимости.
- Пароли хранить только в хешированном виде.

## ENV (без значений)
Минимально важные переменные, которые ИИ должен учитывать при изменениях:
- База данных: `MONGODB_URI`, `MONGODB_KRSK_DBNAME`, `MONGODB_NRSK_DBNAME`, `MONGODB_EKB_DBNAME`
- Auth: `SECRET`
- Auth maintenance: `AUTH_DEV_ONLY_MODE`, `AUTH_DEV_ONLY_ALLOW_PHONES`
- TELEFONIP: `TELEFONIP`
- Telegram: `TELEGRAM_TOKEN_KRSK`, `TELEGRAM_TOKEN_NRSK`, `TELEGRAM_TOKEN_EKB`, `TELEGRAM_BOT_NAME_KRSK`, `TELEGRAM_BOT_NAME_NRSK`, `TELEGRAM_BOT_NAME_EKB`
- WhatsApp: `WHATSAPP_API_URL_KRSK`, `WHATSAPP_API_URL_NRSK`, `WHATSAPP_API_URL_EKB`, `WHATSAPP_ID_INSTANCE_KRSK`, `WHATSAPP_ID_INSTANCE_NRSK`, `WHATSAPP_ID_INSTANCE_EKB`, `WHATSAPP_TOKEN_KRSK`, `WHATSAPP_TOKEN_NRSK`, `WHATSAPP_TOKEN_EKB`
- Email: `EMAIL_SERVICE`, `EMAIL_USERNAME`, `EMAIL_PASSWORD`
- SEO/analytics: `GOOGLE_ANALYTICS_ID`, `YANDEX_METRIKA_ID`, `YANDEX_METRIKA_WEBVISOR`
- Прочее: `DOMAIN`, `MODE`, `TELEGRAM_NOTIFICATION_DEV_ONLY`, `DEEPSEEK_KEY`
